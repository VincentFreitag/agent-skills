# Deck architecture

## Start from the meeting, not the analysis

| Meeting | Length | Shape |
|---|---|---|
| **Steerco pre-read** | 5–10 | Where we are → what we found → what is at risk → what we need from you |
| **Board / exec decision** | 3–6 + appendix | Recommendation → 2–3 supporting arguments → decision needed. Everything else is appendix |
| **Progress update** | 8–15 | Since last time → status by workstream → risks → next milestones |
| **Final report** | 30–60 + appendix | Full pyramid, exec summary carries the whole answer |
| **Workshop pack** | 15–30 | Framing → evidence → open questions → decisions to make in the room |
| **Kick-off** | 10–15 | Context → objectives → approach → workplan → team → ways of working |

The commonest error is writing a final report when the meeting needs a pre-read.
Ask what the audience must *do* and cut to that length.

## SCR — the opening

- **Situation:** what the audience already accepts as true. If they would argue
  with it, it is not situation.
- **Complication:** what changed, what is at risk, what breaks.
- **Resolution:** what should be done.

The complication carries the energy. A deck whose complication is weak reads as
optional. Real examples of complication framing:

> If issues are not addressed, the state's labor shortage is expected to grow
> ~2x by 2024

> Growth projections at risk from supplier product line discontinuation; strong
> need to restructure the portfolio for new drivers

## The pyramid

Governing thought at the top. Beneath it, 2–4 key arguments (these become
sections). Beneath each, the evidence (these become slides). Every level answers
"why?" for the level above and "how do you know?" is answered by the level below.

Test: pick any slide. Can you trace it upward to the governing thought in one
sentence? If not, it is orphan content — appendix or cut.

## Standard skeleton

```
1   Cover
2   Executive summary            ← the whole answer, readable standalone
3   Contents
4   Context / where we left off
5   Section divider: A
6–n Evidence slides for A        ← titles form A's argument
n+1 Section takeaway A
    … repeat per section
—   Recommendations table        (what / rationale / impact / owner / by when)
—   Decisions needed today
—   Next steps
—   Appendix
```

Rules:
- Executive summary is written **last** and must survive being read alone.
- Close every section with its takeaway. Never end a section on new information.
- Recommendations and decisions are separate pages. Merging them lets the room
  nod at the recommendation without deciding anything.
- Appendix carries anything a smart person might challenge you on. Density rules
  relax there; logic rules do not.

## Structuring devices

Use these only where the framework helps the audience decide. A framework introduced for
its own sake costs a page, adds a vocabulary the reader must carry, and buys nothing. If
you cannot name the decision it supports, cut it and state the finding directly.

- **Structure page** — introduce a framework before the section that uses it, so
  every following slide has a home.
- **Tracking element** — repeat the framework marker on each following slide with
  the current element highlighted.
- **Double-click** — a detail slide framed as zooming into one element of the
  prior page. Its title should name the element it zooms into.
- **Leading reference** — start titles with the framework's own words so the
  slide visibly attaches to it.
- **Chapter tracker** — section label in a fixed corner position on every slide.

## Storyline QA

Do this before building a single slide.

1. Write all titles as a numbered list.
2. Read them aloud in order. Where do you have to add a word to make the next one
   follow? That is a missing slide.
3. Where can you delete a title and lose nothing? That is a slide to cut.
4. Does the last title state an action?
5. Does the sequence answer the audience's question, or the order in which the
   team happened to do the work? Analysis order is almost never argument order.

## Consistency checks across the document

- **Data:** subsegments sum to totals stated elsewhere; the same metric has the
  same value on every page it appears.
- **Terms:** one name per thing, everywhere. "Commercial Trading BU" or "the BU",
  not both.
- **Order:** categories appear in the same sequence wherever they recur —
  charts, tables, bullets.
- **Colour semantics:** a segment keeps its colour deck-wide.
- **Time labels:** `FY24` or `2024`, actual/forecast marking, pick one convention.
